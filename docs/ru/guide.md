# Установка и использование

[English](../en/guide.md) · [Українська](../uk/guide.md) · [Русский](guide.md)

## Требования и поддержка

Нужны полный каталог исходников, CPython 3.11–3.13 **64-бит**, современный браузер
и место для архива. Основная проверенная платформа — Windows 10/11 x64. Установка
Linux x64 рассчитана на Ubuntu 24.04 / Debian 12 или новее с подходящим Python;
реальный приём под Linux ещё не принят. Raspberry Pi отложен. Захват работает на
8 MS/s; поддержки пониженной частоты дискретизации для Pi сейчас нет.

Один приёмник и один архив должны принадлежать одному экземпляру приложения.
Закройте другой SDR-софт перед аппаратным приёмом. Начните с демо: оно не открывает
USB и не записывает эфир. Установка скачивает зависимости; во время приёма звук
не отправляется в облако. Node.js 22 нужен только для проверок разработки.

## Windows

После установки и настройки приёмника запускайте **Start RadioMind.cmd** двойным
щелчком из корня проекта. Сервер запустится в фоне, браузер откроется автоматически.
Используется `config/local.yaml`, а при его отсутствии — существующий
`config/hackrf-recorder.yaml`. Повторный щелчок открывает работающую систему;
если приём был остановлен в интерфейсе, он останется остановленным.
Закрытие браузера не останавливает приём — используйте кнопку остановки в интерфейсе.
Ошибки запуска остаются в окне, подробные журналы — в `runtime/windows-launch-*.log`.
Можно создать обычный ярлык на этот CMD-файл на рабочем столе; файл должен оставаться
в каталоге проекта рядом с папкой `scripts`.

Установите Python x64 с доступной командой `python`. В корне исходников выполните:

```powershell
powershell -File scripts/windows/setup.ps1
powershell -File scripts/windows/start.ps1
```

Откройте http://127.0.0.1:8765/. Остановка — Ctrl+C. Установка создаёт `.venv`,
ставит закреплённые зависимости и backend в режиме editable. Драйвер USB она не
меняет и приём не запускает. Не переносите backend отдельно от остального проекта.

Для аналогового приёма установите модель детекции речи и библиотеку HackRF:

```powershell
powershell -File scripts/windows/setup.ps1 -Models -HackRF
```

Нужен совместимый USB-драйвер HackRF. Используйте
[официальную инструкцию HackRF](https://hackrf.readthedocs.io/en/latest/installing_hackrf_software.html).
Скрипты проекта не прошивают устройство. Дополнительно: `setup.ps1 -Cleanup`
устанавливает RNNoise, `setup.ps1 -Digital` — DSD-neo. Сначала прочитайте
[условия сторонних компонентов](../../THIRD_PARTY.md).

Если политика PowerShell блокирует скрипты, запустите `python scripts/bootstrap.py`
и `.venv/Scripts/python.exe -m radiomind` для демо без изменения системной политики.
Дополнительные установщики также можно вызвать напрямую через Python из venv.

## Linux x64

Ubuntu 24.04 / Debian 12:

```sh
sudo apt update
sudo apt install python3 python3-venv libhackrf0 hackrf
sh scripts/linux/setup.sh
sh scripts/linux/start.sh
```

Если системный Python не входит в 3.11–3.13, выберите установленную подходящую
версию: `PYTHON=python3.12 sh scripts/linux/setup.sh`. Используйте venv, без
`sudo pip`. Модель речи: `sh scripts/linux/setup.sh --models`. Цифровой декодер:
добавьте `--digital`; закреплённый AppImage x64 распаковывается без FUSE.
Очистка копий через RNNoise пока только в Windows; Linux сохраняет возможность
приёма и прослушивания оригиналов.

Пакет HackRF предоставляет правила USB. После их установки переподключите устройство
и проверьте доступ обычного пользователя. Не запускайте веб-приложение от root.
Версия системной libhackrf зависит от дистрибутива; pip её не закрепляет.
Для аппаратных проверок сохраните результат `dpkg-query -W libhackrf0`.

## Настройка приёма

Ниже примеры синтаксиса, а не разрешение на конкретные частоты. Замените `XX`,
основание разрешения и диапазон своими данными. Генератор создаёт локальный файл,
исключённый из Git, не перезаписывает существующий и не запускает приём. Для
нескольких диапазонов повторяйте `--range НАЧАЛО:КОНЕЦ` в МГц.

Windows:

```powershell
.venv/Scripts/python.exe scripts/configure.py --country XX --basis "My RX authorization" --range 144:146 --record-audio
.venv/Scripts/python.exe scripts/doctor.py --config config/local.yaml --hackrf-library tools/hackrf/Library/bin/hackrf-0.dll
powershell -File scripts/windows/start.ps1 -Config config/local.yaml -ApproveRx
```

Linux:

```sh
.venv/bin/python scripts/configure.py --country XX --basis "My RX authorization" --range 144:146 --record-audio
RADIO_LIBRARY=$(dpkg -L libhackrf0 | sed -n '/\/libhackrf\.so\.0$/p' | head -n 1)
test -f "$RADIO_LIBRARY"
.venv/bin/python scripts/doctor.py --config config/local.yaml --hackrf-library "$RADIO_LIBRARY"
sh scripts/linux/start.sh --config config/local.yaml --approve-rx --hackrf-library "$RADIO_LIBRARY"
```

В другом дистрибутиве укажите полный путь к `.so`. Проверка `doctor.py` не открывает
USB; успешный результат не означает проверку оборудования. После установки
DSD-neo можно добавить `--digital` при создании профиля. Генератор включает IQ-вход
и пробы DMR/D-STAR/P25-II. Для существующего профиля редактируйте YAML при
остановленном приложении; цифровой режим требует разрешения записи аудио.
TETRA включается отдельно и остаётся экспериментальным.

Выбор USB, усиление и диапазоны из веб-настроек сохраняются в SQLite и при следующем
старте имеют приоритет над YAML. После правки профиля проверьте вкладку «Настройки».
Изменения применяются после текущего разговора; выключение всех диапазонов
останавливает приём. Запускайте только нужные диапазоны с нужными разрешениями.

## Ежедневная работа

- **Записи:** раскройте группу частоты и слушайте записи. В меню можно переименовать
  запись или группу, добавить частоту в избранное либо чёрный список. Удаление
  группы удаляет её записи после подтверждения.
- **Настройки:** конкретный USB HackRF или автоопределение, усиление, диапазоны и
  переключатели их активности. «Сохранить» применяет изменения, «Отмена» отменяет черновик.
- **Слушать эфир:** аналоговый звук во время записи. Предзапись добавляет задержку;
  воспроизведение работает независимо и не блокирует сохранение архива.
- **Очищенная копия:** RNNoise под Windows сохраняет оригинал. Можно сравнить обе
  версии; улучшение зависит от характера шума.
- **Уровень приёма:** превышение оценённого шумового порога в момент захвата, в дБ.
  Это не калиброванная мощность dBm и не оценка разборчивости речи.
- **Диагностика:** ошибки приёма, потери буфера и попытки декодирования. Неизвестный
  формат или одиночная синхронизация не доказывают шифрование либо наличие речи.

Во время удержания разговора сканирование приостановлено: другие частоты можно
пропустить. Предзапись не возвращает сигнал, который был до настройки на частоту.
В созданном профиле сегмент ограничен 180 секундами, архив — 1024 МБ. Для долгой
работы проверьте раздел `audio`: при заполнении квоты новый захват останавливается,
старые записи автоматически не удаляются. Транскрипции, сопровождения транкинга и
обхода шифрования нет. Цифровые форматы экспериментальные: DMR проверен на публичных
референсах, большинство остальных — на синтетике; dPMR/P25-II/TETRA ещё не имеют
полной проверки разборчивого голоса. [Подробная матрица](../en/architecture.md).

## Хранение, обновление и удалённая работа

`data/` — SQLite и аудио, `runtime/` — диагностика, `tools/` — модели и библиотеки,
`config/local.yaml` — начальный профиль. Эти файлы не включаются в экспорт исходников.
Другой диск: `--data-dir ПУТЬ`, в Windows-скрипте `-DataDir ПУТЬ`.
Резервируйте весь каталог данных при остановленном приложении: копирование только
основного SQLite-файла во время записи WAL не даёт согласованной резервной копии.

Перед обновлением остановите приём, сохраните данные и конфигурацию, замените
исходники и повторите setup. Сохраняйте совместимые версии зависимостей и моделей.
Автоматический откат схемы БД не гарантирован. Не запускайте два писателя в один архив.

Авторизации нет, сервер слушает только localhost. Для будущей Linux VM в Proxmox
нужны эксклюзивный USB-проброс и постоянный диск данных. Производительность в VM
не проверена; готового контейнера или инструкции LXC в этом выпуске нет.
Для удалённого доступа со своего компьютера используйте SSH-туннель:

```sh
ssh -N -L 8765:127.0.0.1:8765 user@your-server
```

Откройте обычный локальный адрес. Не публикуйте порт приложения без авторизации.

## Ошибки и проверки

Для DMR требуется повторное подтверждение вызова до принятия декодированного звука.
Поддерживаемые заголовки защиты дают признак шифрования; одна неразборчивость — нет.
В новых захватах объединяются только строго совпадающие дубли выхода слотов;
разные дорожки сохраняются. Короткие вызовы без достаточных заголовков могут остаться
неподтверждёнными. Эти проверки не доказывают разборчивость и не меняют старые записи.

Страница не открывается: посмотрите терминал запуска и порт. Для второго демо
выберите другой порт. Устройство не видно: кабель, драйвер, USB-права и занятость
другим SDR-софтом. Для VM/WSL см.
[диагностику HackRF](https://hackrf.readthedocs.io/en/stable/troubleshooting.html).
Переполнение: сохраните счётчики, уменьшите конкурирующую нагрузку CPU/диска и USB;
не скрывайте пропуски. Не запускайте тяжёлые бенчмарки во время сбора.

Нет модели или декодера: запустите соответствующий установщик и `doctor.py`.
Нет записей: проверьте диапазоны, разрешение записи, уровень сигнала, чёрный список
и квоту. Для баг-репортов используйте синтетику или разрешённые к распространению
референсы; личный эфир не публикуйте.

Запустите `python scripts/check.py` из venv: lint, форматирование, типы, unit/API,
фронтенд и проверка публичного состава. Аппаратные и нативные проверки идут отдельно.
См. [фактические результаты](validation.md) и [правила участия](../../CONTRIBUTING.md).
